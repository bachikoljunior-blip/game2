# M.3 — Tool, engine, scene, and asset automation

**TRIGGER**
The actual technology stack benefits from automated source, editor, engine, scene, build,
browser or asset integration.

**CONTENT**
Detect actual installed or project versions before designing adapters. Use authoritative
documentation, installed types, project source or isolated execution rather than inventing
APIs, methods, parameters or configuration fields.

Automate where useful: source creation, component creation, scene or object construction,
dependency wiring, asset discovery, import and transformation, compression, validation,
metadata, manifests, build and startup, logs, screenshots, video, performance capture, error
extraction.

When external assets exist, maintain enough information to verify source, license,
attribution, version, transformation, runtime cost, compatibility and replacement status. Do
not release unknown-license, incompatible-license or unauthorized assets.

Generated code or assets are not integrated until the real project builds, loads, runs and
behaves correctly.

If direct engine or editor control is unavailable, prepare complete ready-to-apply files and
tests and label them unexecuted.

**STOP CONDITION**
Deactivate when the automation covers the recurring need and further coverage would not
materially reduce cost or error.
