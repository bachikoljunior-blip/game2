# Imported character production assets

These are actual MakeHuman / MPFB assets released under **CC0-1.0**. They are
not images generated by this game and are not content from the fixed comparison
game. See `LICENSE.CC0.md`, the original license comments in each `.mhmat` and
`.mhclo`, and the source/file SHA-256 mapping in `provenance.json`.

The CC0 release names Data Collection AB, Joel Palmius and Jonas Hauquier as
the copyright holders at release. MPFB program code has a different license;
no MPFB program source has been copied into this game. The derivation and runtime
code here were independently written against the supplied data formats.

Source distribution:

- [MPFB asset license](https://github.com/makehumancommunity/mpfb2/blob/master/LICENSE.ASSETS.md)
- [Official MakeHuman system assets](https://static.makehumancommunity.org/assets/assetpacks/makehuman_system_assets.html)
- [MPFB source archive](https://codeload.github.com/makehumancommunity/mpfb2/zip/refs/heads/master)

The moving archive URL is pinned by the acquired archive SHA-256 in
`provenance.json`; every retained source file is separately hashed. `.gz` source
copies decompress byte-for-byte to those source hashes. Original PNGs are
unchanged. No full-body helper boxes, teeth, tongue, genital helpers or original
53-bone skeleton are rendered.

Rebuild the static mesh data with:

```sh
node fresh/character-tools/derive-mpfb.mjs
```

The derivation first applies raw OBJ-coordinate targets to all 19,158 source
vertices. It resolves joint cube/vertex means from that deformed source, fits
eye/hair/brow assets by their actual `.mhclo` entries, and only then extracts the
visible anatomy. UV seams remain separate for rendering. Face normals are
smoothed across source vertices. The hand pose uses every supplied influence;
weights are normalized during the offline bake, without a four-influence truncation.

Finger bone lengths are preserved. Circle/sphere intersections place the phalanges
around the handle, and a unilateral skin-contact projection prevents the LBS
surface from passing through that solid handle. This is a fixed grasp pose,
not a live tendon or soft-tissue simulation. The current pilot keeps that shape
when a hand releases the weapon; a relaxed-hand transition remains unfinished.

The runtime retains the existing 24 articulated joints and CPU-visible static
contact geometry. Each native hand has an anatomical wrist-to-grip offset; arm
IK applies it only while grasping, preserving the existing sword trajectory and
handle targets. The lower head extraction edge is covered by a collar derived
from the same neck surface and extended into the shirt.

## Startup and diagnostics

This pilot explicitly changes the former all-art-generated-at-boot convention:
one imported geometry data module plus four imported PNGs are bundled by Vite.
All requests are to the same origin; there is no runtime MakeHuman request.
`createCharacterResources().ready` waits for all four PNG image decodes.
`createPresentation().assetsReady` exposes that promise. Starting play and scene
rendering wait for success; failures keep the start button disabled and show a
reload message. Node geometry tests return `geometry-only`, never `ready`.

With `?diagnostic`, `freshDiagnostics().actors.assets` reports `state`,
`textureCount`, `pendingCount`, `readyCount`, `failedCount` and `error`. Geometry
is part of the fingerprinted application JS; PNGs retain Vite fingerprinted
filenames. The four PNGs total about 6.6 MB before HTTP transfer encoding. This
is an implementation size, not a mobile performance result.

The optional CPU inspector requires NumPy and Pillow and writes scratch fitting
images. It omits the game's shader, shadow, transparency, tone mapping and frame
timing behavior. Only the subsequent actual WebGL capture can judge the game's
appearance. Neither successful loading, triangle counts nor this asset choice
establishes PS4-level quality.
